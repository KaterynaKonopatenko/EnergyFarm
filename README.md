# EnergyFarm — технічне завдання

Мобільна фінансово-навчальна гра про енергоферму: гравець будує станції, накопичує енергію й торгує нею за реальними історичними цінами ринку електроенергії України.

> **Статус на 23.11.2026:** етап налаштування. Інструменти встановлено, порожній проєкт Godot створюється. **Ігрового коду ще немає.** Формули нижче — це затверджений підхід, а не готова реалізація.

---

## 1. Ідея гри

**Жанр:** економічна симуляція / «ферма» (референси: Монополія, ферма з Warcraft, Hay Day).
**Аудиторія:** усі, з фінансово-навчальним ухилом.
**Мета гри:** показати, як працює енергоринок: виробництво залежить від погоди, ціна від години доби, а прибуток дає вміння зберегти енергію й продати її в дорогу годину.

### Основний ігровий цикл
1. Будуєш станції: сонячні, вітрові, гідро, біогаз, вугільні, атомні.
2. Станції виробляють енергію **залежно від реальної погоди** за ту ігрову дату.
3. Енергію **накопичуєш в акумуляторах (АКБ)** або одразу продаєш.
4. Можна також **купувати** енергію на ринку в дешеву годину й продавати в дорогу (арбітраж).
5. Ціни беруться з **реальних історичних даних РДН** (ринок «на добу наперед»).
6. На зароблені гроші розвиваєш ферму: нові станції, рівні, покращення, більші АКБ.

### Час у грі
- Гра «програє» **минулі роки** реальних даних (наприклад, з 2019 року до сьогодні) погодинно.
- Час прискорений: **1 реальна хвилина = 1 ігрова година** (ігрова доба триває 24 хв). Коефіцієнт має бути в налаштуваннях.

### Меню інвестора
Окремий екран у меню з інформацією про реальні енергетичні проєкти та кнопкою зв'язку (email / Telegram / сайт) щодо інвестування. Контакти надасть замовник.

## 3. Джерела даних

### Ціни: РДН (ринок «на добу наперед»)
- Джерело: **АТ «Оператор ринку»**, https://www.oree.com.ua (результати торгів РДН).
- Формат: погодинні ціни, **грн/МВт·год**, торгова зона ОЕС України.
- У грі зберігаються як CSV: `data/prices/rdn_YYYY.csv`.

```csv
datetime,price_uah_mwh
2023-01-01T00:00,4500.00
2023-01-01T01:00,4200.00
```

### Погода
- Джерело: **Open-Meteo Historical Weather API** (безкоштовне), https://archive-api.open-meteo.com/v1/archive
- Параметри: `hourly=shortwave_radiation,wind_speed_100m&wind_speed_unit=ms`, координати обраного регіону України.
- Зберігається як `data/weather/weather_YYYY.csv`.

```csv
datetime,solar_w_m2,wind_ms
2023-01-01T12:00,310.0,6.4
```

Обидва файли завантажуються **заздалегідь** скриптами з `tools/` і кладуться в гру, тож гра працює офлайн.

## 4. Формули (одна ігрова година, Δt = 1 год)

Позначення: `P` — потужність (кВт), `E` — енергія (кВт·год), `price` — ціна РДН (грн/МВт·год).

### 4.1 Сонячна станція
```
E_solar = P_peak × (G / 1000) × PR × Δt
```
- `P_peak` — пікова потужність панелей, кВт
- `G` — сонячна радіація з погоди, Вт/м² (1000 Вт/м² — стандартні умови)
- `PR` — коефіцієнт ефективності системи, ~0.80
- Вночі `G = 0`, отже `E = 0`.

### 4.2 Вітрова станція (спрощена крива потужності)
```
v < v_in  або  v > v_out        →  P = 0
v_in ≤ v < v_rated              →  P = P_rated × (v³ − v_in³) / (v_rated³ − v_in³)
v_rated ≤ v ≤ v_out             →  P = P_rated
E_wind = P × Δt
```
- Типові значення: `v_in = 3 м/с`, `v_rated = 12 м/с`, `v_out = 25 м/с`
- `v` — швидкість вітру на висоті 100 м з погоди.

### 4.3 Керовані станції (гідро, біогаз, вугілля, атом)
```
E = P_rated × CF × Δt
Витрати = E/1000 × fuel_cost_uah_mwh
```
- `CF` — коефіцієнт використання (атом ~0.9, вугілля ~0.6, біогаз ~0.8, гідро ~0.4); значення уточнити із замовником.
- Атом і вугілля мають паливні витрати та, за бажанням, екологічний штраф.

### 4.4 Акумулятор (АКБ)
```
η_ch = η_dis = √η_rt                      (η_rt — ККД повного циклу, ~0.90)
Заряд:     SOC += min(E_in, P_max × Δt) × η_ch
Розряд:    E_out = min(E_req, P_max × Δt, SOC) × η_dis ;  SOC −= E_out / η_dis
Обмеження: 0 ≤ SOC ≤ Capacity
```
- `SOC` — поточний заряд, кВт·год; `Capacity` — ємність; `P_max` — максимальна потужність заряду/розряду.

### 4.5 Ринок
```
Дохід  = (E_sold   / 1000) × price
Витрата = (E_bought / 1000) × price
Баланс_новий = Баланс + Дохід − Витрата − Витрати_на_паливо − Обслуговування
```
Ділення на 1000 переводить кВт·год у МВт·год.

### 4.6 Ігровий час
```
game_hours_passed = real_seconds × (time_scale / 60)
```
`time_scale = 1.0` означає 1 ігрову годину за реальну хвилину.

## 5. Структура проєкту (план)

Шлях проєкту на машині розробника: `~/Projects/EnergyFarm`

```
EnergyFarm/
├── project.godot
├── README.md
├── scenes/
│   ├── main.tscn              # головна сцена: ферма + HUD
│   ├── ui/
│   │   ├── hud.tscn           # енергія, гроші, годинник, ціна
│   │   ├── shop.tscn          # купівля станцій / АКБ
│   │   └── investor_menu.tscn # контакти щодо інвестування
│   └── stations/
│       ├── solar_panel.tscn
│       ├── wind_turbine.tscn
│       └── battery.tscn
├── scripts/
│   ├── autoload/
│   │   ├── game_clock.gd      # ігровий час (singleton)
│   │   ├── market.gd          # ціни РДН, купівля/продаж
│   │   ├── weather.gd         # погода за поточну ігрову годину
│   │   └── economy.gd         # баланс гравця
│   ├── stations/
│   │   ├── station.gd         # базовий клас станції
│   │   ├── solar_panel.gd
│   │   ├── wind_turbine.gd
│   │   └── dispatchable.gd    # гідро/біогаз/вугілля/атом
│   └── battery.gd
├── data/
│   ├── prices/rdn_YYYY.csv
│   ├── weather/weather_YYYY.csv
│   └── stations.json          # параметри та ціни станцій (баланс гри)
├── assets/
│   ├── sprites/
│   └── fonts/
└── tools/                     # Python, поза грою
    ├── fetch_rdn.py
    └── fetch_weather.py
```

Параметри станцій (`P`, `CF`, вартість, рівні) лежать у `data/stations.json`, а не в коді, щоб баланс можна було змінювати без програмування.

## 7. План робіт

**Етап 1: прототип (MVP)**
1. HUD: енергія, гроші, ігровий годинник.
2. `GameClock`: прискорений час.
3. Одна сонячна панель, яка виробляє тільки вдень (спершу на тестовій кривій).
4. Ціна, що змінюється щогодини (спершу тестові значення).
5. Кнопки «Продати» та «Купити панель».

**Етап 2: реальні дані**
6. Скрипти `tools/` для РДН і погоди → CSV.
7. Підключення CSV до `Market` і `Weather`.
8. АКБ: заряд, розряд, купівля дешевої енергії.

**Етап 3: розширення**
9. Інші типи станцій, рівні та покращення.
10. Меню інвестора.
11. Збереження прогресу, офлайн-дохід.
12. Графіка, звук, збірка під Android.

**Етап 4 (опційно):** бекенд на Railway: хмарні збереження, лідерборд, аналітика.
